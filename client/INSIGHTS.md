## What Works
<!-- Approaches that proved effective here and are not the obvious default -->
- 2026-10-17 — `next build` in `client/` writes the same `.next` the running `next dev` (:3000) uses (`next.config.mjs` has no `distDir`) → while dev runs, build a scratch copy instead: `rsync -a --exclude node_modules --exclude .next client/ <tmp>/ && ln -s "$PWD/client/node_modules" <tmp>/node_modules && cd <tmp> && pnpm exec next build`; works because every `tsconfig.json` alias points inside `client/` (verified green)
- 2026-10-17 — no Chrome extension → visual check with local headless Chrome against the running dev server: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --force-device-scale-factor=2 --window-size=1400,1400 --virtual-time-budget=10000 --screenshot=<scratch>/x.png <url>`, then Read the PNG; works for URL-driven state (`/pulls/<n>?tab=findings`). The PR list filter is local state defaulting to "Needs review" (rows without findings), so there drive Chrome over CDP (`--remote-debugging-port`, click "All", `Page.captureScreenshot`); the shell's Node is v20 → run the script with `node --experimental-websocket`
- 2026-10-18 — follow-up to 2026-10-17 "no Chrome extension": hover-only UI (FINDINGS popover) opens over CDP with `Input.dispatchMouseEvent {type:"mouseMoved"}` at the centre of the trigger's `getBoundingClientRect()` (found via `[aria-label$="in the latest run of each agent"]`), after clicking "All" through `Runtime.evaluate`; set `Emulation.setDeviceMetricsOverride` 1400×900 @2x → verified screenshot with the popover open

## Codebase Patterns
<!-- Conventions and architecture decisions (with the reason) not stated in CLAUDE.md -->
- 2026-10-12 — `src/vendor/shared` differs from `server/src/vendor/shared` (adapters.ts, contracts/{eval-ci,knowledge,productionize,trace}.ts) → diff both copies before relying on a contract.
- 2026-10-17 — Cost/token display goes through `src/lib/cost.ts` (`formatCost`, `formatTokenCount`) and `components/RunCostBadge`; missing data renders "—", never "$0.00" → don't format USD inline in a component
- 2026-10-17 — PR-detail severity filter lives in the URL (`?severity=`, `SeverityFilter/` + `FindingsPanel/helpers.ts#visibleFindings`), like `?tab=`/`?trace=` → extend the same `setParam` in `pulls/[number]/page.tsx` for new PR-level view state; parse with `parseSeverity`, never trust the raw param
- 2026-10-17 — Zod `Severity` (`vendor/shared/contracts/findings.ts:11`) has 3 levels but the UI token `Severity` (`vendor/ui/primitives/tokens.ts:3`) also has `INFO` → key per-level UI on the Zod type so `INFO` can't leak into filters/counters
- 2026-10-17 — supersedes 2026-10-17 "PR-detail severity filter lives in the URL": severity pills + Critical/Warning/Suggestion toggles are now per Review-run card, local `useState` (`client/src/app/repos/[repoId]/pulls/[number]/_components/FindingsPanel/FindingsPanel.tsx:31`); counts come from the same `visibleFindings` as the list minus the severity step (`FindingsPanel.tsx:37`) so a pill always equals the cards shown → derive counts and list from one source; there is no `?severity=` param any more
- 2026-10-17 — evidence for 2026-10-12 "`src/vendor/shared` differs": `git diff --no-index --stat server/src/vendor/shared/contracts client/src/vendor/shared/contracts` lists eval-ci, knowledge, productionize, trace → platform.ts/findings.ts are identical, mirror any edit to them into both copies (`contracts/platform.ts` `PrFindingPreview`)
- 2026-10-17 — evidence for 2026-10-17 "Cost/token display": formatters are `formatCost` (`src/lib/cost.ts:12`) and `formatTokenCount` (`src/lib/cost.ts:20`); the Timeline uses `RunCostBadge` at `client/src/app/repos/[repoId]/pulls/[number]/_components/RunHistory/RunHistory.tsx:202`
- 2026-10-17 — PR-list findings popover is `position: fixed` from `getBoundingClientRect` (`client/src/app/repos/[repoId]/pulls/_components/FindingsPopover/helpers.ts#popoverPosition`) because the table card has `overflow: hidden` (`client/src/app/repos/[repoId]/pulls/styles.ts:90`) and clips an absolutely positioned child → keep fixed positioning; bridge the trigger↔panel gap with padding, not margin, or the hover drops
- 2026-10-17 — design mock of the PR list orders columns Score · FINDINGS · Status · Cost · Updated and draws FINDINGS as bare icon+count with a dotted underline, no pill → keep `COLUMN_KEYS`/`GRID` in `client/src/app/repos/[repoId]/pulls/constants.ts:27` in sync with the mock and style the trigger via `FindingsPopover/styles.ts#count`, not `SeverityBadge` (pill background)
- 2026-10-17 — timeline `RunSummary` (`vendor/shared/contracts/trace.ts`) has only `findings_count`/`blockers`, no per-severity split; the page already loads each run's findings via `usePrReviews`, matched on `ReviewRecord.run_id` (`client/src/app/repos/[repoId]/pulls/[number]/_components/FindingsTab/FindingsTab.tsx:75`) → derive per-run severity UI from that map, don't extend the runs endpoint; live API check: every done run matched its review and the counts summed to `findings_count`
- 2026-10-17 — "PR cost ≠ sum of its runs" (e.g. 2 × `$0.0001` but list `$0.0003`) was display rounding, not a SUM bug: real costs 0.000129 + 0.000134 = 0.000263 → check exact `agent_runs.cost_usd` (or the badge tooltip) before touching the server SUM; sub-cent costs now use 2 significant digits (`formatCost`, `client/src/lib/cost.ts`) so runs and sum round alike, keep it that way
- 2026-10-18 — `FindingsPopover` has two modes: `groups` (`PrAgentFindings[]`, PR list → one section per agent, icons summed via `flattenGroups`) and flat `findings` (one run, Timeline `RunHistory.tsx:200`) → pass `PrMeta.findings_by_agent` as `groups` from `PRRow`, never flatten it upstream or the per-agent sections are lost (`client/src/app/repos/[repoId]/pulls/_components/FindingsPopover/FindingsPopover.tsx`)
- 2026-10-18 — styling is style objects in each folder's `styles.ts` (`style={s.x}` in 34 non-vendor `.tsx`), `className` only for global utility classes (`mono`, `tnum`, `skeleton`, `dd-md`), although root AGENTS.md lists Tailwind 4 and react-best-practices says "utility classes, no style objects" → follow `styles.ts`, don't write Tailwind class strings (`grep -rl 'style={s\.' src --include='*.tsx'`; `src/components/RunCostBadge/styles.ts`)
- 2026-10-18 — supersedes 2026-10-12 "`src/vendor/shared` differs" and its 2026-10-17 evidence: the client copy is now byte-identical to `server/src/vendor/shared`, regenerated by `./scripts/sync-shared.sh` and guarded by `--check` in CI `shared-contracts.yml` → never edit `client/src/vendor/shared` by hand
- 2026-10-18 — component tests wrap `NextIntlClientProvider` with only the namespaces they import (e.g. `{ agents }`), so wiring a shared component to a NEW namespace (`useTranslations("common")`) breaks its parents' tests, not the component's own → add that namespace to the test messages (`AgentEditor.test.tsx` gained `common`) and run the whole `pnpm test`, not just the edited file
- 2026-10-18 — data layer: each `src/lib/hooks/<domain>.ts` owns a key factory (`reviewKeys`, `pullKeys`, …) + `queryOptions` builders, and GETs pass a `@devdigest/shared` schema to `api.get(path, Schema)`; a mismatch throws `ApiError` 502 `invalid_response` (`src/lib/api.ts:78`), which the global query handler toasts (≥500) → invalidate via the factory, never inline arrays; a 502 `invalid_response` toast means client/server contract drift, not an API outage (`src/lib/api.test.ts`)
- 2026-10-18 — PR-list filters `?status&q&sort` are written with `window.history.replaceState` (`pulls/hooks/usePullListParams.ts:21`), not `router.replace`: the route is dynamic (ƒ), so `router.replace` per keystroke refetches its RSC payload, while Next 15 syncs native history calls into `useSearchParams` → use the same for any high-frequency URL state
- 2026-10-18 — code used by a parent route and its child lives in the nearest common ancestor (`pulls/_lib/severity.ts` for `FindingsPopover` + `SeverityFilter`), never in a sibling's `_components` (the old `FindingsPopover` → `[number]/_components/SeverityFilter` import) → check `rg '\.\./\.\./\[' src/app` for upward-then-down imports

## Recurring Errors & Fixes
<!-- Error message → root cause → fix -->
- 2026-10-17 — Next build error "Module not found: Can't resolve './contracts/findings.js'" in `vendor/shared/index.ts` → a runtime (non-`import type`) import from `@devdigest/shared` (e.g. the Zod `Severity`); webpack can't map the `.js` re-exports, vitest can, so tests stay green → import only types from `@devdigest/shared` in client code, and check with `pnpm exec next build`, not just `pnpm test` (hit in `SeverityFilter/helpers.ts`)
- 2026-10-17 — TS2719 "Two different types with this name exist, but they are unrelated" on a `@devdigest/shared` type → the real cause is the nested `Types of property 'X' are incompatible` line (e.g. a test fixture missing a newly added contract field), not a duplicate type → read the last lines of the error and fix the fixture (`RunHistory.test.tsx` after adding `RunSummary.cost_usd`)
- 2026-10-17 — every page returns 500 with "Cannot find module './975.js'" (stack: `client/.next/server/webpack-runtime.js`) while `next dev` keeps running → stale `.next` chunk cache after a long-lived dev server plus a second `./scripts/dev.sh`; API stays healthy → stop `next dev`, `rm -rf client/.next`, restart (`pnpm dev` in `client/`); verified: `/repos/<id>/pulls` 500 → 200
- 2026-10-18 — `PRRow.test.tsx` "Found multiple elements with the text: —" → not only FINDINGS renders "—": Score, Cost and Updated (`updated_at: null` in the `pr()` fixture) do too → assert the FINDINGS cell by its aria-label (`queryByLabelText(/findings in the latest run/)`), not by `getByText("—")`
- 2026-10-18 — TS2349 "This expression is not callable" on `t("…")` after adding `const t = useTranslations(…)` → an inner variable named `t` (in `lib/toast.tsx` the toast in `toasts.map((t) => …)`) shadows the translator → name the translator after its namespace (`tCommon`) in files that already use `t` as a local
- 2026-10-18 — supersedes 2026-10-17 "Next build error 'Module not found: Can't resolve './contracts/findings.js''": `next.config.mjs:13` maps `.js` → `.ts/.tsx/.js` via webpack `resolve.extensionAlias`, so runtime imports of Zod schemas from `@devdigest/shared` build (verified with scratch `next build`) → runtime imports are fine now; if the error returns, check that alias first
- 2026-10-18 — `ERR_PNPM_PACKAGE_MANAGER_REMOVE_MODULES_DIR` / pnpm wanting to reinstall in `client/` → a scratch build ran `pnpm exec next build` in a `/tmp` copy with `node_modules` symlinked, and pnpm 12 rewrote `client/node_modules/.pnpm-workspace-state-v1.json` with the `/tmp` project path → fix: `pnpm install --frozen-lockfile --offline` (full permissions; lockfile untouched); in scratch copies run `./node_modules/.bin/next build`, never `pnpm exec`
