# DevDigest

Local-first AI pull-request review. Course starter: each lesson (L01–L08) adds one feature.
Overview + architecture: [README.md](README.md) · Test strategy: [TESTING.md](TESTING.md)

## Stack
- All: Node ≥22 · pnpm ≥10 · TypeScript 5.7 · Zod 3.24 · Vitest 2
- server: Fastify 5 · Drizzle 0.38 · Postgres + pgvector (only Postgres runs in Docker)
- client: Next.js 15 (App Router) · React 19 · Tailwind 4 · TanStack Query 5 · next-intl

## Map
| Path | What |
|------|------|
| [server/](server/AGENTS.md) | API :3001 — DB, GitHub/git/LLM adapters, repo-intel indexer |
| [client/](client/AGENTS.md) | Next.js studio :3000 |
| [reviewer-core/](reviewer-core/AGENTS.md) | Pure engine: diff → prompt → LLM → grounded findings |

| .claude/skills/ | Stack skills — catalog in [.claude/skills/README.md](.claude/skills/README.md) |

Before editing a package, read `<pkg>/AGENTS.md` and `<pkg>/INSIGHTS.md` if not already in context,
and name in one line the insights that apply (or "none").

## Commands
```sh
./scripts/dev.sh                 # Postgres + migrate + seed + API + web (--help for flags)
cd <pkg> && pnpm typecheck && pnpm test
docker compose down -v           # full DB reset
/pr-self-review                  # (in Claude Code) review open changes; a CRITICAL blocks git push / gh pr create
git config core.hooksPath .githooks   # once per clone: enables the pre-push gate
```

## Rules
- NOT a monorepo: each package has its own package.json + lockfile. Run pnpm inside the package, never at root.
- Cross-package code only via path aliases (`@devdigest/shared`, `@devdigest/reviewer-core`).
  New alias → add to BOTH `tsconfig.json` and `vitest.config.ts` of the package.
- Shared Zod contracts are COPIED: `server/src/vendor/shared` is canonical → edit it, then run
  `./scripts/sync-shared.sh` to mirror into `client/src/vendor/shared`. CI (`shared-contracts.yml`)
  fails on drift; never edit the client copy by hand.
- Done = typecheck + tests green in every package you touched, plus the `engineering-insights` pass
  (see "Insights (every task)") before reporting done.
- `AGENTS.md` is canonical (root + every package); `CLAUDE.md` next to it is a symlink to it for Claude Code.
  Edit `AGENTS.md`; never replace the `CLAUDE.md` symlink with a regular file.

## Naming conventions
- Files/folders: `kebab-case` (`run-executor.ts`, `repo-intel/`, `reviewer-core/`). Exceptions: client component
  folders and their `.tsx` are `PascalCase` (`RunCostBadge/RunCostBadge.tsx`); Next.js route segments follow the
  URL (`[repoId]`, `_components/` for page-private code).
- Tests: `X.test.ts(x)` next to the code (client) or in `test/` (server, reviewer-core); DB-touching server tests
  are `*.it.test.ts`; e2e flows are `NN-name.flow.json`; feature specs are `L<NN>-<feature>.md`.
- Code: `camelCase` variables/functions, `PascalCase` types/components/Zod schemas (`Severity`, `FindingRecord`),
  `UPPER_SNAKE_CASE` constants (`GRID`, `SIZE_COLOR`), `use…` for hooks.
- Wire/DB: JSON contracts and DB columns are `snake_case` (`cost_usd`, `run_id`); Drizzle fields are `camelCase`
  (`costUsd`). Map between them at the repository/route boundary, never in the UI.
- i18n: namespaced `camelCase` keys in `client/messages/en/<ns>.json`, nested by area (`finding.accept`).

## Insights (every task)
After EVERY task that touches a package — not only big ones — run the `engineering-insights` skill: write any
non-obvious, verified finding into that package's `INSIGHTS.md` with date and `path:line` evidence, or say
explicitly that nothing passed the quality gate. Do this as you go, without being asked.

## Do not touch
- `server/clones/` — repos cloned by the app (gitignored). Contains OTHER copies of dev-digest;
  never read, search or edit them as our code.
- `server/src/db/migrations/` — generated by `pnpm db:generate`; never hand-edit.
- `.env*` files (secrets) · `pnpm-lock.yaml` (no manual edits).

## Per-package docs (read on demand, not upfront)
Every package has the same layout:
- `README.md` — overview + diagrams
- `docs/` — deep-dives and decision notes
- `specs/` — feature specs; read the matching one before implementing a lesson (e2e: `docs/specs/`)
- `INSIGHTS.md` — agent-written learnings in 7 fixed sections; append-only via the `engineering-insights` skill
