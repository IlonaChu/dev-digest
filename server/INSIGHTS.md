- 2026-10-18 — supersedes the `src/modules/pulls/routes.ts:171` locations in the 2026-10-17 "PR list `cost_usd`" and 2026-10-18 "`findings_by_agent`" entries: routes are thin now — SQL in `src/modules/pulls/repository.ts` (`doneRunCostByPr`, `reviewsNewestFirst`, `findingPreviewsByReview`), orchestration + GitHub sync/backfill in `pulls/service.ts`, pure mappers in `pulls/domain.ts` (`test/pulls-domain.test.ts`) → change rules there; finding previews are fetched only for the latest review per agent, not all reviews
- 2026-10-18 — any read of a file inside a clone must go through `readFileInsideRoot` (`src/adapters/fs/safe-read.ts`): it rejects `../`/absolute paths via `resolveInsideRoot` (`src/platform/safe-path.ts`) AND re-checks after `realpath`, because a committed symlink in a cloned repo passes the lexical check (`test/safe-path.test.ts`) → never `readFile(join(clonePath, p))`; git argv puts `--` before a path (`simple-git.ts` blame/log)
- 2026-10-18 — the global error handler (`src/app.ts`, generic branch) answers every 5xx as `internal_error` / "Internal error" and only passes through 4xx `statusCode`s → a 500's real message is only in the server log (pino `err`), not in the HTTP body or the client toast; throw `AppError`/`NotFoundError` for anything the user should read
- 2026-10-18 — PR import is ONE `INSERT … ON CONFLICT (repo_id, number) DO UPDATE SET col = excluded.col` (`PullsRepository.upsertFromGitHub`, `src/modules/pulls/repository.ts`), shared by list sync and `POST /repos/:id/poll`; the input is de-duplicated by `number` first because Postgres refuses to update the same row twice in one statement → keep the dedupe if the GitHub adapter starts paging/merging lists; idempotency pinned in `test/integration.it.test.ts:115`
- 2026-10-18 — supersedes the 2026-10-18 Open Questions on repo-intel layering and raw `readFile`: the indexer reaches disk/parser only through module-owned ports `SourceTree`/`CodeParser`/`Tokenizer` (`src/modules/repo-intel/ports.ts`), implemented by `NodeSourceTree` (root-confined via `readFileInsideRoot`) and `AstGrepCodeParser` in `src/adapters/`, picked in `platform/container.ts:154,161` → new clone I/O or parsing goes behind these ports; test stubs must provide `sourceTree`/`codeParser` (`test/indexer-pipeline.test.ts`)
- 2026-10-18 — multi-statement writes take `db: DbExecutor` (`Db | DbTx`, `src/db/client.ts:11`) so one helper serves both plain and transactional calls; a run's review+findings+PR head+run completion commit atomically in `ReviewRepository.persistRunOutcome` (`src/modules/reviews/repository.ts:88`), symbol re-index in `RepoIntelRepository.rewriteSymbols` (`src/modules/repo-intel/repository.ts:251`) → add new multi-writes as one repository method wrapping `db.transaction`, never sequential awaits from a service
- 2026-10-18 — `agent_runs.status` is guarded by DB CHECK `agent_runs_status_check` (`running|done|failed|cancelled`, `src/db/schema/runs.ts:24,36`, migration `0011_high_skrulls.sql`) → a new run status needs the enum + check edited and `pnpm db:generate`, otherwise inserts fail with a check violation; an existing DB needs `pnpm db:migrate`

## Tool & Library Notes
<!-- Dependency/tool quirks, version-specific behaviour -->
- 2026-10-12 — `*.it.test.ts` self-skip without Docker, so a green `pnpm test` may not have run them → check the output when touching SQL/routes.
- 2026-10-17 — evidence for 2026-10-12 "`*.it.test.ts` self-skip": the gate is `dockerAvailable()` in `test/helpers/pg.ts:23` (runs `docker info`, 5s timeout) → with Docker up, `pnpm test` ran 22 files / 130 tests including the IT ones
- 2026-10-17 — local DB shell: `docker compose exec -T postgres psql -U devdigest -d devdigest` (role/db from `docker-compose.yml:9-11`); `-U postgres` fails with 'role "postgres" does not exist' → back up before destructive SQL with `pg_dump -U devdigest -d devdigest --data-only -t <table>…` to a scratch file
- 2026-10-18 — dependency-cruiser under pnpm resolves npm imports to the versioned real path (`node_modules/.pnpm/drizzle-orm@0.38.4_postgres@3.4.9/…`), so baseline entries would break on every upgrade → keep `preserveSymlinks: true` in `.dependency-cruiser.cjs` (paths become `node_modules/drizzle-orm/…`); verified by re-running `depcruise --output-type err`
- 2026-10-18 — the local pnpm is 12.4.2 and rejects `pnpm -s <script>` ("unexpected argument '-s' found") → run scripts without `-s` (`pnpm arch:check`)
- 2026-10-18 — Fastify validates an ABSENT request body as `null`, not `undefined`, so `schema.body: X.optional()` answers 422 "Expected object, received null" for a body-less POST → use `X.nullish()` and `req.body ?? {}` (`src/modules/reviews/routes.ts` `/pulls/:id/review`, pinned in `test/reviews.it.test.ts`)
- 2026-10-18 — `src/adapters/depgraph/index.ts` used a literal NUL byte as a key separator, so `file` reported "data" and editor/agent Read tools refused it as binary → write control chars as escapes (`\u0000`), never raw bytes; find them with `python3 -c "…b'\x00' in open(p,'rb').read()"`
- 2026-10-18 — in the Cursor agent sandbox `docker info` fails, so `dockerAvailable()` (`test/helpers/pg.ts:23`) returns false and every `*.it.test.ts` silently self-skips while `pnpm test` is still green → run `pnpm test` with sandbox disabled (full permissions) and confirm the IT files appear in the output (verified: 24 files / 151 tests with IT)
- 2026-10-18 — follow-up to 2026-10-18 "`src/adapters/depgraph/index.ts` used a literal NUL byte": the same raw NUL separator was also in `src/modules/repo-intel/pipeline/repo-map.ts:64` (now `\u0000`) → scan the whole `src/` with the python check, not just the file you are editing
