## What Works

- 2026-10-19 — a fetch-based adapter is unit-tested hermetically against a loopback `node:http` `createServer` on `127.0.0.1:0` (redirect, `content-length` over the cap, chunked body cut mid-stream, 404) — no outside network, so it stays out of `*.it.test.ts` (`test/url-fetcher.test.ts`); attach `res.on('error')` / `req.socket.on('error')` no-ops in the handler so a client-side `reader.cancel()` cannot crash the test process
- 2026-10-19 — supersedes 2026-10-19 "a fetch-based adapter is unit-tested hermetically against a loopback": `FetchUrlFetcher` now refuses non-public addresses by default, so loopback tests construct it with `{ allowPrivateHosts: true }`; to test a redirect into the network, inject `resolve` mapping `127.0.0.1` to a public IP and the target host to a private one (`test/url-fetcher.test.ts` "checks every redirect hop")

- 2026-10-12 — `*.it.test.ts` self-skip without Docker, so a green `pnpm test` may not have run them → check the output when touching SQL/routes.
- 2026-10-17 — evidence for 2026-10-12 "`*.it.test.ts` self-skip": the gate is `dockerAvailable()` in `test/helpers/pg.ts:23` (runs `docker info`, 5s timeout) → with Docker up, `pnpm test` ran 22 files / 130 tests including the IT ones
- 2026-10-17 — local DB shell: `docker compose exec -T postgres psql -U devdigest -d devdigest` (role/db from `docker-compose.yml:9-11`); `-U postgres` fails with 'role "postgres" does not exist' → back up before destructive SQL with `pg_dump -U devdigest -d devdigest --data-only -t <table>…` to a scratch file
- 2026-10-18 — dependency-cruiser under pnpm resolves npm imports to the versioned real path (`node_modules/.pnpm/drizzle-orm@0.38.4_postgres@3.4.9/…`), so baseline entries would break on every upgrade → keep `preserveSymlinks: true` in `.dependency-cruiser.cjs` (paths become `node_modules/drizzle-orm/…`); verified by re-running `depcruise --output-type err`
- 2026-10-18 — the local pnpm is 12.4.2 and rejects `pnpm -s <script>` ("unexpected argument '-s' found") → run scripts without `-s` (`pnpm arch:check`)
- 2026-10-18 — Fastify validates an ABSENT request body as `null`, not `undefined`, so `schema.body: X.optional()` answers 422 "Expected object, received null" for a body-less POST → use `X.nullish()` and `req.body ?? {}` (`src/modules/reviews/routes.ts` `/pulls/:id/review`, pinned in `test/reviews.it.test.ts`)
- 2026-10-18 — `src/adapters/depgraph/index.ts` used a literal NUL byte as a key separator, so `file` reported "data" and editor/agent Read tools refused it as binary → write control chars as escapes (`\u0000`), never raw bytes; find them with `python3 -c "…b'\x00' in open(p,'rb').read()"`
- 2026-10-18 — in the Cursor agent sandbox `docker info` fails, so `dockerAvailable()` (`test/helpers/pg.ts:23`) returns false and every `*.it.test.ts` silently self-skips while `pnpm test` is still green → run `pnpm test` with sandbox disabled (full permissions) and confirm the IT files appear in the output (verified: 24 files / 151 tests with IT)
- 2026-10-18 — follow-up to 2026-10-18 "`src/adapters/depgraph/index.ts` used a literal NUL byte": the same raw NUL separator was also in `src/modules/repo-intel/pipeline/repo-map.ts:64` (now `\u0000`) → scan the whole `src/` with the python check, not just the file you are editing
- 2026-10-19 — Fastify answers 400 to a DELETE that carries `content-type: application/json` with an empty body (a raw `urllib`/curl `-H` call), while the client's `apiFetch` only sets the header when there is a body → when scripting the API, omit the header on body-less requests
- 2026-10-19 — `test/architecture.test.ts` scans every `src/**` file for `process.env`, including prose in seed prompts/skill bodies → don't write that literal into seeded text (found while writing the Test Quality skills)
- 2026-10-19 — follow-up to 2026-10-19 "`pnpm db:generate` stops on an interactive prompt": a default-only change (`.default('accepted')` → `.default('pending')`) generates without any prompt, `pnpm db:generate < /dev/null` is enough and emits a single `ALTER COLUMN … SET DEFAULT` (migration 0014) → the pty trick is only needed when a migration both adds and drops columns
- 2026-10-19 — drizzle-orm 0.38 `update(t).set({})` throws a plain `Error('No values to set')`, which the generic handler turns into `500 internal_error`; `PUT /skills/:id` with `{}`, only `version_message`, or an unchanged body hit it → build the SET object first and skip the UPDATE when it is empty (`SkillsRepository.update`, pinned in `test/skills-routes.it.test.ts`)
- 2026-10-19 — fflate 0.8.3 `unzipSync` inflates each entry into a FIXED buffer of the header's declared `originalSize` (`inflt`: `resize = noBuf || st.i != 2`, `node_modules/.pnpm/fflate@0.8.3/.../lib/node.cjs`) → output never exceeds the declared size (a lying header truncates the text), so a `byteLength > maxBytes` re-check after `unzipSync` is dead code; filter on `originalSize` is the real cap (`src/adapters/archive/fflate.ts`)
- 2026-10-19 — `node:net` `BlockList.check(addr, 'ipv6')` also matches IPv4-mapped addresses (`::ffff:127.0.0.1`, `::ffff:a9fe:a9fe`) against IPv4 subnets, and WHATWG `URL` normalises `0x7f.1` / `2130706433` to `127.0.0.1` → one BlockList of IPv4+IPv6 ranges covers those bypasses (`isNonPublicAddress` in `src/adapters/http/url-fetcher.ts`)
- 2026-10-20 — supersedes 2026-10-19 "fflate … fixed buffer" (dead `byteLength` check): that holds for DEFLATED entries only; a STORED entry (compression 0) is sliced by its real compressed size, so a zip with a lying central-directory size returned 600 KB past a 256 KB cap → keep the post-read `bytes.byteLength > maxBytes` check in `readText` (server/src/adapters/archive/fflate.ts:52, test/archive-fflate.test.ts)
