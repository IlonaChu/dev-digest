# L01 — Run Cost Badge (server)

## Goal
Persist and expose the USD cost of every agent run so the UI can show it. Cost is data we already
have — `reviewer-core` returns `outcome.costUsd` (OpenRouter `usage.cost`, else tokens × price via
`PriceBook`/`estimateCost`) — it was simply dropped by `run-executor`. **Zero extra model calls.**

## Scope
**In**
- `agent_runs.cost_usd` (nullable `double precision`) written when a run completes.
- `cost_usd` on the run timeline (`RunSummary`), the run trace (`RunStats`) and the PR list (`PrMeta`).

**Out**
- Backfill of runs created before this feature (they stay `null` → UI shows "—").
- Summing cost per PR or per multi-agent batch (there is no `batch_id`; see Open points).
- CI runs (`ci_runs.cost_usd` is a separate table), price-book changes, the PR Overview verdict card.

## API / contracts
Canonical in `server/src/vendor/shared/contracts`, mirrored by hand into `client/src/vendor/shared`
(the copies have drifted — apply the same edits, never copy the file).

| Contract | Change |
|---|---|
| `trace.ts` › `RunStats` | `cost_usd: number \| null \| undefined` — nullish so traces persisted earlier still parse |
| `trace.ts` › `RunSummary` | `cost_usd: number \| null` — `GET /pulls/:id/runs` |
| `platform.ts` › `PrMeta` | `cost_usd: number \| null \| undefined` — `GET /repos/:id/pulls`, list endpoint only |

DB: `ALTER TABLE agent_runs ADD COLUMN cost_usd double precision` — migration `0010_*` generated by
`pnpm db:generate` (never hand-edited); apply with `pnpm db:migrate`.

Semantics: `null` = unknown (model has no price, failed/cancelled run, or pre-feature run). `0` = a
genuinely free model. Never store `0` for "no data".

`GET /repos/:id/pulls` → `cost_usd` is the cost of the **run that produced the latest review** of that
PR (resolved `reviews.run_id → agent_runs.cost_usd`, one extra `IN` query, no N+1); `null` if the PR was
never reviewed or that run has no cost.

## Acceptance criteria
1. A completed run stores `agent_runs.cost_usd = outcome.costUsd`; `run_traces.stats.cost_usd` matches.
2. Failed / cancelled runs store `null`.
3. `GET /pulls/:id/runs` returns `cost_usd` per run.
4. `GET /repos/:id/pulls` returns the latest review's run cost, `null` when unreviewed.
5. A trace without `stats.cost_usd` still passes `RunTrace.parse`.
6. The number of LLM calls per review is unchanged (test: stored cost == calls × mock price).
7. `pnpm typecheck && pnpm test` green (integration tests must actually run — Docker up).

## Open points / deviations
- "Latest review" is a single run. With *Review all* (several agents), the list shows one agent's cost,
  not the batch total. A real batch total needs a `batch_id` on `agent_runs`.

## Update 2026-10-17
Supersedes the PR-list wording in "API / contracts" and "Open points" above (the other contracts are unchanged).

**`cost_usd` on `GET /repos/:id/pulls` is now the SUM over all runs of the PR.** `src/modules/pulls/routes.ts`
runs one grouped query: `SELECT pr_id, sum(cost_usd) FROM agent_runs WHERE pr_id IN (...) AND status = 'done' GROUP BY pr_id`.
- Only `status = 'done'` runs count; failed/cancelled runs are excluded.
- SQL `SUM` ignores `NULL` costs. A PR with no done run, or whose done runs are all unpriced, gets no
  row and so `cost_usd = null` (never `0`). A PR mixing priced and unpriced done runs shows the sum of the priced ones.
- This resolves the "Review all shows one agent's cost" open point: several agents (or re-runs) now add up.
  There is still no `batch_id`, so a batch cannot be separated from earlier runs of the same PR.
- Pinned by `test/reviews.it.test.ts` (a second run doubles the listed cost: `calls * 0.001 * 2`).

**PR list items now also carry `findings: PrFindingPreview[]`.** They are the findings of the PR's latest
review (newest `reviews` row with `kind = 'review'`), read with one `IN` query on `findings.review_id`;
`[]` when the PR was never reviewed. Fields: `id`, `severity`, `category`, `title`, `file`, `start_line`,
`end_line`, `confidence`, `rationale`. The client uses them for the findings popover on the PR row.
"Latest review" is one agent's review, so with *Review all* the popover shows only the most recent agent's findings.
- Contract: `PrFindingPreview` and `PrMeta.findings` (`nullish`, list endpoint only) in
  `src/vendor/shared/contracts/platform.ts`; mirror to `client/src/vendor/shared/contracts/platform.ts`.
- `score` still comes from that same latest review. Computing score, findings and cost costs three queries
  per list call (reviews, findings, grouped cost), none per PR, no LLM call.
- Pinned by `test/reviews.it.test.ts` (`listed.findings` has the one grounded CRITICAL on `src/config.ts:11`).

## Update 2026-10-18
Supersedes the `findings` / `score` wording of "Update 2026-10-17" (cost is unchanged: still the SUM over done runs).

**Findings and score count the latest review of EACH agent, not the single newest review of the PR.**
Review feedback: after *Review all* the list showed only the last agent's findings, so the numbers hid the other agents.
- `PrMeta.findings` is replaced by `findings_by_agent: PrAgentFindings[]` (`nullish`, list endpoint only):
  `{ agent_id, agent_name, run_id, score, findings: PrFindingPreview[] }`, one entry per agent. Contract in
  `src/vendor/shared/contracts/platform.ts`, mirrored to the client.
- Grouping (`latestReviewPerAgent` in `src/modules/pulls/status.ts`): reviews are read newest-first with
  `leftJoin(agents)`; the first row per `(pr_id, agent_id)` wins, so a re-run of one agent replaces its findings and
  never adds to them. Reviews with `agent_id = null` (seed/legacy) form one group. Groups are sorted by agent name;
  `agent_name = null` (no agent or a deleted one) goes last and the UI labels it "Unknown agent".
- `score` = rounded average of the groups' non-null scores (`averageScore`); `null` when no group has one.
- Still three queries per list call (reviews+agents, findings by `review_id IN (...)`, grouped cost), no N+1, no LLM call.
- Pinned by `test/pulls-status.test.ts` (grouping, ordering, average) and `test/reviews.it.test.ts`
  (same agent re-run → still 1 group / 1 finding; a second agent → groups `Perf`, `Sec`; score = average).
- Known data caveat: a review whose `agent_runs` row was removed outside `deleteAgentRun` still counts (it is
  still listed in the PR's Review runs), even though the Timeline no longer shows that run.
